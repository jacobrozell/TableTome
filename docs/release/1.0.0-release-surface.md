# 1.0.0 release surface — Spearhead / AoS only

**Status:** Active for App Store 1.0.0  
**Last updated:** 2026-10-28  
**Code:** [`Support/ReleaseSurface.swift`](../../Support/ReleaseSurface.swift)  
**Spec:** [`specs/ReleaseSurfaceSpec.md`](../../specs/ReleaseSurfaceSpec.md)  
**Tests:** [`Tests/Unit/ReleaseSurfaceTests.swift`](../../Tests/Unit/ReleaseSurfaceTests.swift)

This document is the **verbose agent map** for what ships in 1.0.0 vs what stays in the bundle but hidden. Read this before changing Play, Rules, Settings, or onboarding.

---

## One-line summary

**1.0.0 ships Age of Sigmar Spearhead only** for play, guided match, rules reference, and settings game-guide links. **Models (Collection + Paints) is not game-system gated.** 40k, Combat Patrol, and StarCraft remain in the repo and bundle for dogfood via launch arguments.

---

## What users see in Release (no launch args)

| Tab / area | Visible in 1.0.0 | Notes |
|------------|------------------|-------|
| **Play** | Spearhead only | Home list + new-player chooser |
| **Guided Match** | `aos-spearhead` only | Entry from Play, game guide, onboarding |
| **Rules** | Spearhead rule sections + glossary | No game-system picker (only one system) |
| **Settings → New here?** | “Open Spearhead guide” only | No 40k / CP / StarCraft buttons |
| **Models** | Collection + Paints | All factions/armies in hobby data — **intentionally not gated** |
| **Lists (Muster)** | Hidden | `-enable_full_product_surface` |
| **Rules Q&A (search tab)** | Hidden | Rules tab shows browse-only `RulesReferenceView` |

## API cheat sheet (which function for which pillar)

Use **existing** APIs — do not add ad-hoc `gameSystemId == .aosSpearhead` checks in feature UI unless Spearhead-specific copy/layout.

| Question | Call | Typical file |
|----------|------|--------------|
| Show this game on **Play home**? | `ReleaseSurface.isPlayHomeGameSystemVisible(_:)` | `HomeViewModel`, `HomeNewPlayerChooserCard` |
| Show in **Rules** picker / load rules bundle? | `ReleaseSurface.isGameSystemVisible(_:)` | `RulesReferenceViewModel`, `AppDependencies` |
| Show **Settings** guide shortcut? | `ReleaseSurface.isGameSystemIdVisible(_:)` | `SettingsView`, `OnboardingContent` |
| Show **Guided Match** link / open match? | `ReleaseSurface.showsGuidedMatch(for:)` | `GameGuidePlayLinksSection`, `GuidedMatchDestinationView` |
| Show **Combat Resolver** tool? | `ReleaseSurface.showsCombatResolver(for:)` | `GameGuidePlayLinksSection`, combat roll UI |
| Show **Lists** tab? | `ReleaseSurface.showsMusterTab` | `RootTabView`, `BenchTab` |
| Show **Rules search** tab vs browse? | `ReleaseSurface.showsRulesAssistant` | `RootTabView` |

**Defense in depth:** `GuidedMatchDestinationView` and `GameSystemDetailView` re-check gates on load so deep links cannot bypass the surface.

## Launch arguments

Set in **Xcode → Edit Scheme → Run → Arguments Passed On Launch**. Defined in `Support/AppLaunchArguments.swift`.

| Argument | Unlocks |
|----------|---------|
| `-enable_full_product_surface` | All bundled game modes, Lists tab, Paints (already on), Rules Q&A tab, StarCraft, 40k 10e stub row, cross-pillar roster→play links |
| `-enable_all_play_modes` | 40k 11e + Combat Patrol on **Play home only** (Rules/Settings still Spearhead-only unless full surface) |
| `-enable_combat_patrol` | Combat Patrol visibility paths that check `showsCombatPatrol` |

**Shortcuts (combine with surface args as needed):**

| Argument | Effect |
|----------|--------|
| `-skip_onboarding` | Skip app tour |
| `-open_guided_match` | Jump to Guided Match (Spearhead in release) |
| `-apply_starter_matchup` | Pre-fill Skaventide-style starter armies |
| `-onboarding_choice aos-spearhead` | Persist onboarding game pick |

## Ungating checklist (post-1.0)

When promoting 40k, Combat Patrol, or StarCraft to release defaults:

1. Update `liveReleaseGameSystemIds` and related booleans in `ReleaseSurface.swift`
2. Update [`specs/ReleaseSurfaceSpec.md`](../../specs/ReleaseSurfaceSpec.md) gates table
3. Update [`docs/feature-inventory.md`](../feature-inventory.md)
4. Complete manual QA in [`gated-features-testing.md`](gated-features-testing.md) for that mode
5. Fix `ReleaseSurfaceTests` expected sets
6. Playbook: [`docs/development/playbooks/ungate-feature.md`](../development/playbooks/ungate-feature.md)
